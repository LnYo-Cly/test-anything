## test-anything v0.4.0

## English

Classify cases and run only the ones you need, and get the exact line and column of every structural mistake in a case file.

### Features

- Cases may declare `project`, `suite`, `layer` and `tags`. `ta run` selects them with repeatable `--project`, `--suite`, `--layer` and `--tag`, and excludes them with `--skip-tag`: values of one option are alternatives, different options must all match, `--skip-tag` wins. `layer` is free-form.
- Every discovered file is still validated before filtering, so a filter never hides a broken case. Filters that select nothing exit 2 and list the values the cases actually use.
- The classification appears in text and JSON results, `meta.json`, `ta schema` and `ta lint --output json` (new `cases` list); the summary counts `filtered` cases.
- Structural errors in a step, an assertion, a `save` entry or a variable now name the line and column and show the source snippet, in both `ta lint` and `ta run`.

### Fixes

- Paths in text, JSON and failure bundles use `/` on every platform.
- YAML syntax errors keep their multi-line source snippet.
- `ta schema` now agrees with the parser: case names may be numbers or booleans, blank classification values are rejected, and `timeout_ms` must be at least 1.
- Step names are checked when a step is registered.

### Documentation

- `docs/guide.md` explains how to run cases against a service you start yourself, that `--output` may stand before or after the subcommand, and how to capture JSON output in Windows PowerShell.

### Install

Linux and macOS:

```sh
curl -fsSL https://raw.githubusercontent.com/LnYo-Cly/test-anything/main/install.sh | sh
```

Windows:

```powershell
irm https://raw.githubusercontent.com/LnYo-Cly/test-anything/main/install.ps1 | iex
```

Or download the archive for your platform below, extract it, and put `ta` on your `PATH`. Verify the download with `SHA256SUMS`.

## 中文

给用例分类，只运行需要的那部分；用例文件中的每个结构错误都给出准确的行号和列号。

### 功能

- 用例可以声明 `project`、`suite`、`layer`、`tags`。`ta run` 用可重复的 `--project`、`--suite`、`--layer`、`--tag` 选择，用 `--skip-tag` 排除：同一选项的多个值是"或"，不同选项必须同时满足，`--skip-tag` 优先。`layer` 是自由字符串。
- 筛选前仍校验所有发现的文件，筛选不会隐藏有问题的用例。筛选结果为空时退出 2，并列出用例实际使用的取值。
- 分类字段出现在文本与 JSON 结果、`meta.json`、`ta schema` 以及 `ta lint --output json`（新增 `cases` 列表）中；汇总统计被筛掉的用例数 `filtered`。
- 步骤、断言、`save` 条目或变量的结构错误现在给出行号、列号和源码片段，`ta lint` 与 `ta run` 相同。

### 修复

- 文本、JSON 与失败包中的路径在所有平台都使用 `/`。
- YAML 语法错误保留多行源码片段。
- `ta schema` 与解析器一致：用例名可以是数字或布尔值，空白的分类值被拒绝，`timeout_ms` 至少为 1。
- 注册步骤时校验步骤名。

### 文档

- `docs/guide.md` 说明如何对自己启动的服务运行用例、`--output` 可以写在子命令前后，以及如何在 Windows PowerShell 中捕获 JSON 输出。
