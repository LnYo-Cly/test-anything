## test-anything v0.5.0

## English

Verify more than the response: read the database and the log a step touched, keep secrets out of every output, and run cases in parallel.

### Features

- `db.query` runs one read-only query against SQLite (`sqlite:path`) or PostgreSQL (`postgres://`) and returns `columns`, `rows`, `row_count` and `truncated` for `expect` and `save`. Parameters bind by position; `max_rows` and `timeout_ms` bound the work. Writes and statement lists are refused at two layers (a read-only connection and a read-only, rolled-back transaction), and the database is never created.
- `observe:` declares read-only observers that run around every step; their results appear under `observed.<name>` before the assertions run, and in failure bundles. The first one, `log.file`, reports the lines a step added to a log file, with truncation and a 1 MiB cap.
- `--vars-file` (repeatable) loads variables from YAML; `--var` still wins. `${env:NAME}` reads an environment variable, and every value read that way is replaced with `***` in text and JSON output, error messages and failure bundles.
- `--jobs N` runs up to N cases at once. Results, output order, failure bundles and exit codes are the same as a serial run.
- `ta schema` and `ta lint` describe and check `observe` and `db.query`, with line and column for every problem.

### Fixes

- Errors about a step now name the line and column, with a snippet, in both `ta lint` and `ta run`: an unregistered step, invalid or unknown arguments, and an undefined variable.
- A duplicate key is reported with "keep each key once" instead of a parser option name.
- The guide asserts on an observation with `text` (a substring) rather than `lines` (whole entries), and shows how to give each case its own log under `--jobs`.

### Notes

- The release binary is larger because it now bundles SQLite and a PostgreSQL client. Build with `--no-default-features` and the features you need for a smaller binary.

## 中文

不止验证响应：读取步骤影响到的数据库和日志，让机密不出现在任何输出中，并行运行用例。

### 功能

- `db.query` 对 SQLite（`sqlite:路径`）或 PostgreSQL（`postgres://`）执行一条只读查询，返回 `columns`、`rows`、`row_count`、`truncated`，可用于 `expect` 与 `save`。参数按位置绑定；`max_rows` 与 `timeout_ms` 限定工作量。写语句和多条语句在两层被拒绝（只读连接，以及只读且总会回滚的事务），数据库文件不会被创建。
- `observe:` 声明只读观察者，在每个步骤前后运行；结果在断言之前并入 `observed.<名字>`，也写入失败包。第一个观察者 `log.file` 报告步骤期间日志文件新增的行，处理截断并限 1 MiB。
- `--vars-file`（可重复）从 YAML 加载变量，`--var` 仍然优先。`${env:NAME}` 读取环境变量，这样读到的值在文本与 JSON 输出、错误信息和失败包中都替换为 `***`。
- `--jobs N` 同时运行最多 N 个用例；结果、输出顺序、失败包与退出码和串行一致。
- `ta schema` 与 `ta lint` 描述并检查 `observe` 与 `db.query`，每个问题都给出行列号。

### 修复

- 步骤相关的错误在 `ta lint` 与 `ta run` 中都给出行号、列号和源码片段：未注册的步骤、无效或未知的参数、未定义的变量。
- 重复键的提示改为"每个键只写一次"，不再出现解析器的选项名。
- 指南改用 `text`（子串匹配）而不是 `lines`（整行相等）断言观察结果，并说明 `--jobs` 下如何让每个用例使用独立的日志文件。

### 说明

- 发布的二进制变大了，因为内置了 SQLite 和 PostgreSQL 客户端。需要更小的二进制时，用 `--no-default-features` 加上所需 feature 自行构建。
